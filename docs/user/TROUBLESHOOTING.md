# Решение проблем

Сначала запишите браузер и версию, ОС, версию расширения, выбранный Automatic
routing source, используемые Proxy connections и текущий режим Auto / Proxy /
Direct. Не публикуйте пароли, приватные endpoints, URL с query string, cookies,
routing data или историю посещений.

> Названия разделов соответствуют доверенной ветке `main`. В опубликованном ZIP
> `v0.0.2.3` расположение элементов может быть старше, но безопасные действия
> и значения endpoints остаются теми же.

## Setup required: настройка не завершена

**Что это значит.** Расширению не хватает выбранного источника или другой
обязательной части конфигурации. Это не намеренный режим Off.

**Что сделать.**

1. Откройте Options из popup.
2. В **Automatic routing** выберите встроенный source или **Manual rules only**.
3. Если есть явные Proxy rules, убедитесь, что хотя бы одно Proxy connection
   включено и корректно.
4. Нажмите глобальный **Apply configuration**.
5. Проверьте в Overview состояние **Routing is active**.

## Routing is Off

**Что это значит.** Пользователь намеренно выключил управление прокси. Правила и
загруженные данные сохранены, но Chromium использует системную конфигурацию.

**Что сделать.** Откройте Overview или popup и примените сохранённую
конфигурацию. Не очищайте хранилище: Off не означает повреждение настроек.

## Изменения показывают Not applied

**Что это значит.** Источник, Site rule или Proxy connection сохранены как
черновик, но активные правила Chromium ещё не изменились.

**Что сделать.**

1. Исправьте показанные рядом ошибки.
2. Нажмите существующий глобальный **Apply configuration**.
3. Дождитесь результата и проверьте Overview.
4. Обновите вкладку сайта, если требуется повторить уже начатые запросы.

Сохранение поля, Enabled или reorder не должны применять конфигурацию
автоматически.

## Прокси контролируется извне (`EXT`)

**Что это значит.** Другое расширение или политика браузера владеет proxy
settings. Runet Censorship Bypass уважает владельца и не перезаписывает чужую
настройку.

**Что сделать.**

1. Проверьте список расширений и отключите другой VPN/proxy manager, только если
   вы понимаете его назначение.
2. Проверьте `chrome://policy` или соответствующую страницу браузера, если
   устройство управляется организацией.
3. Вернитесь в Overview и примените конфигурацию после освобождения настройки.

Если владелец — машинная политика, изменить её может только администратор. Не
меняйте системный прокси вслепую.

## Явный Proxy не имеет доступного подключения

**Что это значит.** Proxy rule должен использовать пригодное настроенное
подключение и не подменяется намеренным Direct или политикой источника. Поэтому
Apply блокируется, если такого подключения нет.

**Что сделать.**

1. Откройте **Proxy connections**.
2. Проверьте счётчик доступных подключений.
3. Включите и исправьте нужный локальный или пользовательский proxy server.
4. Нажмите **Save proxy settings**, затем глобальный **Apply configuration**.
5. При необходимости запустите вторичную Connection check в Maintenance.

Не включайте случайный сервер только ради прохождения проверки.

## Tor, Tor Browser или WARP недоступен

**Что это значит.** Enabled сообщает, что подключение разрешено для
маршрутизации, но не запускает локальное приложение и не обнаруживает его
автоматически.

**Что сделать.**

- Для **Tor service** запустите локальную службу и проверьте SOCKS5
  `127.0.0.1:9050`. Автоматического fallback на 9150 нет.
- Для **Tor Browser** запустите Tor Browser и проверьте SOCKS5
  `127.0.0.1:9150`. Автоматического fallback на 9050 нет.
- Для **WARP** запустите настроенный локальный proxy и проверьте текущее
  значение `SOCKS5 127.0.0.1:40000; HTTPS 127.0.0.1:40000`. Автоматического
  обнаружения WARP нет.

Раскройте **Edit** рядом с проблемной строкой, исправьте endpoint только если
локальное приложение действительно использует другое значение, сохраните и
нажмите глобальный Apply. Затем повторите Connection check вручную.

## Пользовательский proxy server не работает

**Что это значит.** Причиной может быть некорректный host/port/type,
незапущенный сервер или отдельная проблема аутентификации. Известная ошибка
показывается рядом со строкой; свёрнутая строка не раскрывает credentials.

**Что сделать.**

1. Нажмите **Edit** у нужной строки.
2. Исправьте подсвеченный host, port или type.
3. Если требуется credential, используйте явное действие замены или удаления
   пароля. Пустое replacement field не должно показывать сохранённый пароль.
4. Сохраните Proxy settings и нажмите глобальный Apply.
5. Запустите Connection check в Maintenance.

Успешное сетевое соединение и успешная proxy-auth — разные вещи. Не копируйте
реальный username, password или приватный host в issue.

## Обновление routing data завершилось ошибкой

**Что это значит.** Automatic routing source не был загружен или принят.
Предыдущую активную конфигурацию нельзя считать обновлённой, пока интерфейс явно
не подтвердит успех.

**Что сделать.**

1. Проверьте обычное соединение с сетью.
2. Для custom source используйте HTTPS либо loopback HTTP.
3. Удалите логин и пароль из URL: такие адреса отклоняются.
4. Попробуйте встроенный source, чтобы отделить ошибку собственного сервера.
5. Учтите ограничения загрузки: 30 секунд, не более 16 MiB и корректный UTF-8.
6. Откройте Maintenance и сохраните только очищенный диагностический статус.

Не публикуйте полный приватный URL, query string или содержимое routing data.

## Connection check failed

**Что это значит.** Ручная проверка не смогла пройти по сохранённому целевому
адресу с текущей конфигурацией. Она не меняет маршрут, не запускает приложение,
не сохраняет черновик и не является Apply.

**Что сделать.**

1. Убедитесь, что нужный source или Proxy connection уже сохранён и применён.
2. Запустите локальное приложение или проверьте доступность сервера.
3. Проверьте endpoint и настройку аутентификации через Edit.
4. Повторите Connection check из Maintenance.
5. Сравните с синтетическим тестовым сайтом, чтобы отделить проблему маршрута от
   проблемы конкретной страницы.

Даже успешная проверка не доказывает отсутствие DNS-утечек, маршрут каждого
вспомогательного запроса или аутентификацию всех соединений.

## Правило сайта выглядит неверно

**Что это значит.** Возможно, черновик ещё не применён, выбрана другая область
правила или более приоритетное явное правило перекрывает Auto.

**Что сделать.**

1. Проверьте Auto / Proxy / Direct в popup.
2. Убедитесь, что рядом нет **Not applied**.
3. Сверьте область: точный host или домен с поддоменами.
4. Для IP и `localhost` используйте точный host.
5. Откройте **Site rules** и найдите конфликт: явный Direct имеет приоритет над
   явным Proxy.
6. После успешного Apply обновите вкладку.

Не делайте вывод о DNS-маршруте только по значку или одному запросу страницы.

## Расширение не загружается

**Что это значит.** Чаще всего выбран не тот каталог или распакованная папка
была перемещена.

**Что сделать.**

1. Проверьте SHA-256 архива и распакуйте его заново.
2. Выберите папку, где `manifest.json` виден непосредственно в корне.
3. Не выбирайте ZIP, корень репозитория или внешний каталог.
4. Откройте `chrome://extensions` и нажмите **Reload**.
5. Убедитесь, что постоянная папка расширения остаётся на месте.

Готовая локальная сборка разработчика находится в
`extensions/chromium/runet-censorship-bypass/build/extension-chromium-mv3`,
но обычному пользователю следует брать ZIP из
[GitHub Releases](https://github.com/aVitomin/runet-censorship-bypass-mv3/releases).
Подробности — в [инструкции по установке](INSTALLATION.md).

## Интерфейс постоянно показывает Working

**Что это значит.** Операция или страница могла не завершить обмен с фоновым
процессом.

**Что сделать.**

1. Нажмите **Reload** на карточке расширения.
2. Закройте и снова откройте popup или Options.
3. Если ожидание не исчезло, откройте service worker / Inspect views и
   воспроизведите проблему один раз.
4. Скопируйте только релевантную очищенную ошибку.

Не очищайте local storage первым шагом: это удаляет настройки и усложняет
диагностику.

## Собрать безопасный диагностический отчёт

1. Сначала используйте очищенные события и отчёт в **Maintenance**.
2. Если этого недостаточно, откройте DevTools нужной страницы или service
   worker, очистите консоль и воспроизведите проблему один раз.
3. Перед публикацией удалите passwords, usernames, proxy endpoints, tokens,
   cookies, query parameters, profile IDs, локальные пути, посещённые URL и
   routing data.
4. Не прикладывайте браузерный профиль, NetLog или сырую историю без отдельного
   согласования: они могут содержать чувствительные данные.

Для обычной ошибки используйте
[шаблон issue](https://github.com/aVitomin/runet-censorship-bypass-mv3/issues/new/choose).
О потенциальной уязвимости сообщайте по
[политике безопасности](../../SECURITY.md).
