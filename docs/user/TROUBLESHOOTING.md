# Решение проблем

Сначала запишите браузер и версию, ОС, версию расширения, способ установки,
выбранный источник, метод прокси и текущий режим A/P/D. Не публикуйте приватные
URL или учётные данные.

## Расширение не загружается

1. Проверьте SHA-256 архива.
2. Распакуйте его заново.
3. Выберите папку, где непосредственно находится `manifest.json`.
4. Не выбирайте ZIP, внешний каталог репозитория или каталог исходного кода.
5. Если Chromium показывает конкретную ошибку manifest, скопируйте только её
   текст без локального пути профиля.

Готовая локальная сборка для разработчика находится в
`extensions/chromium/runet-censorship-bypass/build/extension-chromium-mv3`, но
обычному пользователю следует брать ZIP из GitHub Releases.

## Выбрана неверная папка manifest

Ошибка `Manifest file is missing or unreadable` почти всегда означает лишний
уровень каталога. Откройте выбранную папку в файловом менеджере: `manifest.json`
должен быть виден в её корне.

## Расширение постоянно загружается

1. Откройте `brave://extensions` или `chrome://extensions`.
2. Нажмите **Reload** на карточке расширения.
3. Закройте и снова откройте popup.
4. Если ожидание не исчезло, откройте ссылку **service worker / Inspect views**
   на карточке и проверьте одну воспроизводимую ошибку.
5. Убедитесь, что файлы распакованной папки не были удалены или заменены во
   время работы браузера.

Не очищайте локальное хранилище первым шагом: это удаляет настройки и усложняет
диагностику.

## Прокси контролируется извне (`EXT`)

Расширение уважает владельца настройки и не перезаписывает другую политику.

1. Откройте список расширений и временно отключите другие менеджеры VPN/proxy.
2. Проверьте `brave://policy` или `chrome://policy`, если браузер управляется
   организацией.
3. Вернитесь в popup и нажмите проверку статуса.

Если настройкой владеет политика, изменить её может только администратор.

## Proxy connection failed

1. Проверьте, что выбранный метод включён и процесс/сервер действительно
   запущен.
2. Сверьте тип, хост и порт; не публикуйте их, если endpoint приватный.
3. Для собственного прокси отдельно проверьте необходимость аутентификации.
4. Сохраните раздел, нажмите **Apply configuration**, затем повторите health
   check.
5. Попробуйте синтетический тестовый сайт, чтобы отделить проблему прокси от
   проблемы конкретного сайта.

Ошибка соединения не всегда означает ошибку PAC; успешный ответ не гарантирует
маршрут всех вспомогательных запросов страницы.

## Tor Browser и порт 9150

Включите метод **Tor Browser** и запустите Tor Browser до проверки. По умолчанию
ожидается SOCKS5 на `127.0.0.1:9150`. Если Tor Browser закрыт или использует
другую конфигурацию, соединение не установится. Не путайте этот метод с
локальным Tor service на порту 9050.

## Ошибка загрузки провайдера или PAC

1. Проверьте обычное соединение с сетью.
2. Для пользовательского источника используйте HTTPS либо loopback HTTP.
3. Удалите логин/пароль из URL; такие адреса отклоняются.
4. Попробуйте встроенный источник, чтобы отделить ошибку пользовательского
   сервера.
5. Учтите ограничения загрузки: 30 секунд, не более 16 MiB и корректный UTF-8.
6. Не вставляйте полный приватный URL или PAC-тело в issue.

Предыдущий применённый PAC не следует считать обновлённым, пока интерфейс явно
не подтвердил новое применение.

## Правило текущего сайта кажется неверным

1. Проверьте, показывает ли значок A, P или D для активной вкладки.
2. Убедитесь, что изменение не ожидает **Apply configuration**.
3. Сверьте область: точный хост или домен и поддомены.
4. Для localhost/IP используется только точный хост.
5. Проверьте конфликтующие правила в **Site rules**. Явный Direct имеет приоритет
   над явным Proxy.
6. Обновите вкладку после успешного применения.

Не делайте вывод о DNS-маршруте только по значку или одному запросу страницы.

## Выключить прокси расширения

Используйте **Turn off extension proxy** в popup или настройках. Это сохраняет
правила и PAC-кэш. После успеха значок показывает `OFF`, а Chromium использует
системную конфигурацию.

Если показан `EXT`, это расширение уже не владеет настройкой и не может очистить
чужую политику. Не меняйте системный прокси вслепую.

## Собрать очищенный вывод консоли

1. На странице расширений откройте DevTools service worker.
2. Для popup или options откройте DevTools именно этой страницы.
3. Очистите консоль, воспроизведите проблему один раз и скопируйте только
   релевантные ошибки.
4. Перед публикацией удалите пароли, логины, proxy endpoints, токены, cookies,
   query-параметры, идентификаторы профиля, локальные пути, посещённые URL и
   PAC-тело.
5. Не прикладывайте браузерный профиль, NetLog или сырую историю без отдельного
   согласования: они могут содержать чувствительные данные.
