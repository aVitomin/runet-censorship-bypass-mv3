# Руководство пользователя

Интерфейс разделяет глобальное управление прокси Chromium и правила для
конкретного сайта. Сохранённое изменение становится активным только после
применения конфигурации.

## Первичная настройка

При чистой установке раздел **Overview** показывает компактные три шага:

1. выберите источник в **Automatic routing**;
2. при необходимости настройте подключение в **Proxy connections** — для
   обычной автоматической маршрутизации это необязательно;
3. нажмите **Apply configuration**.

Выбор источника и сохранение настроек сами по себе не меняют маршрут Chrome.
После успешного применения карточка первичной настройки исчезает. Если позже
нажать **Turn off extension proxy**, расширение сохраняет намеренно выключенное
состояние и не показывает его как незавершённую первичную настройку.

## Глобальное управление

### Apply configuration

Единая кнопка **Apply configuration** сохраняет подготовленные настройки,
обновляет и проверяет PAC, строит итоговые правила, проверяет их актуальность и
применяет их к Chromium. Если на странице настроек есть несохранённый черновик,
сначала сохраните или отмените его.

Успешный статус `Active` означает, что это расширение управляет PAC-настройкой
Chromium. Он не утверждает, что каждый внешний прокси доступен.

### Turn off extension proxy

Кнопка **Turn off extension proxy** сохраняет авторитетное выключенное состояние
и снимает PAC-настройку этого расширения. Если прокси уже контролирует другое
расширение или политика, внешняя настройка не изменяется, а скрытая PAC-настройка
этого расширения удаляется после возврата управления. В остальных случаях
Chromium возвращается к системной настройке прокси. Правила сайтов, выбранный
источник, прокси-подключения и загруженные данные сохраняются.

После полного перезапуска Chromium/Brave расширение может восстановить только
тот PAC, который ранее успешно применило: сохранённая конфигурация,
происхождение и хэш артефакта должны совпадать, а живое состояние браузера
должно разрешать управление. Если последним действием был **Turn off / Clear**,
прокси остаётся выключен. Управление другого расширения или политики не
перезаписывается.

## Маршрут текущего сайта

Popup показывает хост активной вкладки и три режима:

- **Auto** удаляет явное правило для сайта. Решение принимает выбранный
  источник.
- **Proxy** создаёт явное правило и использует включённые прокси-подключения. Без
  доступного Tor, WARP или пользовательского прокси-сервера такой режим применить
  нельзя.
- **Direct** создаёт явное правило обхода прокси расширения.

Для обычного домена можно выбрать точный хост или домен с поддоменами. Границы
домена определяются с учётом публичных суффиксов. Для IP-адреса и localhost
доступен только точный хост.

Изменение текущего сайта и глобальный выключатель — разные действия. Правило
можно подготовить при выключенном прокси, но оно начнёт влиять на трафик только
после **Apply configuration**.

## Автоматическая маршрутизация

Раздел **Automatic routing** содержит:

- **Antizapret** — основной встроенный PAC-источник;
- **Anticensority** — альтернативный встроенный PAC-источник;
- **Manual rules only** — исходно прямой маршрут и только ваши явные правила;
- пользовательские источники — один или несколько доверенных PAC URL.

Для пользовательского источника разрешён HTTPS. HTTP допустим только для
loopback-адресов при локальном тестировании. URL с логином или паролем
отклоняется. Добавляйте только источник, которому доверяете: PAC определяет
маршрутизацию запросов Chromium.

Смена источника сохраняет настройку, но активная PAC-конфигурация не меняется
до **Apply configuration**.

## Правила сайтов

Раздел **Site rules** позволяет просматривать, добавлять, менять и удалять
правила Auto/Proxy/Direct. Обычный шаблон совпадает только с точным хостом;
шаблон `*.example.com` совпадает с `example.com` и его поддоменами.

Приоритет маршрутизации: явный Direct, явный Proxy, пропуск whitelist,
специальная обработка `.onion`, затем политика источника. Не создавайте
конфликтующие правила без необходимости; интерфейс должен показывать итоговый
шаблон перед сохранением.

## Прокси-подключения

Раздел **Proxy connections** управляет подключениями для явного режима Proxy:

- локальный Tor service, обычно SOCKS5 `127.0.0.1:9050`;
- Tor Browser, обычно SOCKS5 `127.0.0.1:9150`;
- локальный режим WARP, по умолчанию порт `40000`;
- пользовательские HTTP, HTTPS, SOCKS4 или SOCKS5 прокси-серверы.

Tor service и Tor Browser — разные локальные процессы; включайте фактически
запущенный вариант. Tor Browser должен оставаться открытым для порта 9150.

Для пользовательского прокси-сервера задаются тип, хост, порт и необязательные
учётные данные. После сохранения пароль больше не показывается. При изменении
endpoint явно выберите сохранение, замену или удаление пароля; это защищает от
случайного переноса учётных данных на другой сервер.

По безопасным умолчаниям пользовательские прокси-серверы используются только для
ваших Proxy-правил. Широкая замена Direct и удаление Direct из результатов —
экспертные настройки, а не обязательный режим работы.

## Проверка подключения

Раздел **Maintenance** показывает обновление PAC и последнюю
проверку прокси. Для содержательной проверки нужен уже применённый Proxy-маршрут
и известный целевой сайт. Любой HTTP-ответ подтверждает сетевую достижимость;
ошибки Chromium о прокси являются более сильным сигналом.

После запуска расширение планирует проверку актуального подключения примерно через
30 секунд. Успешный результат считается свежим один час, затем обновляется.
Proxy-specific failure повторяется через 1, 5, 15, 30 и 60 минут; дальнейшие
повторы ограничены одним разом в час. Неоднозначная сетевая ошибка без
browser-сигнала о proxy также проверяется позднее и не выдаётся за доказанный
отказ proxy.

Ошибка, сохранённая в предыдущей browser session, после нового запуска не
показывается как свежая. Поэтому Tor Browser или пользовательский прокси-сервер,
запущенный позже браузера, может восстановиться автоматически; успешная проверка
снимет предупреждение. Кнопка **Check proxy** запускает немедленную проверку и
после успеха сбрасывает backoff.

Автоматическая проверка подключения не меняет A/P/D, PAC, выбранный источник или
владельца proxy settings.

Проверка доступности и успешная аутентификация — разные вещи. Результат также
не доказывает отсутствие DNS-утечек или маршрут каждого запроса страницы.

## Значок панели инструментов

| Значок | Значение |
| --- | --- |
| `A` | Прокси расширения активен; текущий сайт в Auto. |
| `P` | Активно явное Proxy-правило. |
| `D` | Активно явное Direct-правило. |
| `OFF` | Прокси расширения выключен. |
| `EXT` | Прокси контролируется другим расширением или политикой. |
| `…` | Идёт применение, обновление, выключение или проверка. |
| `!` | Ошибка, устаревшая активная конфигурация или проблема подключения. |

Внутренняя страница браузера может не иметь режима A/P/D, хотя глобальное
управление остаётся включено.

## Семь разделов настроек

1. **Overview** — глобальный статус и следующее безопасное действие.
2. **Automatic routing** — встроенные и пользовательские PAC-источники.
3. **Site rules** — точные и доменные правила.
4. **Proxy connections** — Tor, WARP и пользовательские прокси-серверы.
5. **Maintenance** — расписание, обновление, проверка подключения и очищенная
   диагностика.
6. **Advanced** — редкие политики, миграция и экспертные операции.
7. **About** — версия, выпуск, ссылки проекта, лицензия и атрибуция.

Если интерфейс или маршрут ведёт себя иначе, используйте
[руководство по решению проблем](TROUBLESHOOTING.md).
