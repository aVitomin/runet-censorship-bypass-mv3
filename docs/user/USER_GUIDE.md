# Руководство пользователя

Runet Censorship Bypass выборочно управляет маршрутом сайтов в Chromium. Options
нужны для настройки и применения конфигурации, а компактный popup — для
ежедневного выбора маршрута текущего сайта.

Названия и структура ниже соответствуют опубликованному выпуску `v0.0.3.0`.

## 1. Первая настройка

При незавершённой настройке popup показывает **Setup required** и открывает
Options.

1. Откройте **Automatic routing**.
2. Выберите источник:
   - **Antizapret** или **Anticensority** для встроенной автоматической
     маршрутизации;
   - **Manual rules only**, если должны действовать только ваши явные правила;
   - доверенный custom source, если вы заранее понимаете его назначение и риски.
3. Если нужны явные правила Proxy, откройте **Proxy connections** и включите хотя
   бы одно пригодное подключение.
4. Нажмите глобальную кнопку **Apply configuration**.
5. В **Overview** убедитесь, что показано **Routing is active** и сохранённая
   конфигурация совпадает с активными правилами.

Apply остаётся единым действием, которое меняет маршрутизацию Chromium.
Сохранение источника, правила или proxy endpoint создаёт черновик; пока он не
применён, интерфейс показывает **Not applied**.

Если источник способен маршрутизировать сайты без ваших Proxy connections,
локальный или пользовательский прокси для Auto не обязателен. Явному режиму
Proxy, напротив, требуется хотя бы одно доступное настроенное подключение.

## 2. Popup и ежедневное использование

Откройте нужную вкладку и нажмите значок расширения. В popup расположены:

1. компактное глобальное состояние;
2. имя текущего сайта;
3. **Auto / Proxy / Direct**;
4. свёрнутые подробности и вторичные действия.

### Auto, Proxy и Direct

- **Auto** удаляет явное исключение для выбранной области сайта и следует
  политике выбранного Automatic routing source.
- **Proxy** создаёт явное правило, которое использует доступные настроенные
  Proxy connections. В маршруте не добавляется намеренный Direct или результат
  источника. Если пригодного подключения нет, Apply блокируется и предлагает
  исправить Proxy connections.
- **Direct** создаёт явное правило, обходящее прокси расширения для выбранной
  области сайта.

Для обычного hostname можно выбрать точный хост или домен с поддоменами. Для IP,
`localhost` и других случаев без регистрируемого домена доступен только точный
хост. Явный Direct имеет приоритет над явным Proxy; после него применяется Auto.

Изменённое правило показывает рядом **Not applied** и использует существующую
кнопку **Apply**. Автоматического применения нет. После успешного Apply обновите
страницу сайта, если нужно повторить уже начатые запросы.

### Глобальное состояние

- **Active** — расширение управляет proxy settings браузера.
- **Off** — управление намеренно выключено; правила и загруженные данные
  сохранены.
- **Setup required** — ещё нет пригодной применяемой конфигурации; это не то же
  самое, что намеренный Off.
- **Controlled externally / EXT** — настройкой владеет другое расширение или
  политика; Runet Censorship Bypass не перехватывает управление.
- **Working / …** — операция ещё выполняется.
- **Needs attention / !** — требуется открыть подробности или Options.

**Turn off extension proxy** возвращает Chromium к системной конфигурации, если
расширение владеет настройкой. Команда не удаляет сохранённые правила или кэш.

## 3. Automatic routing

Этот раздел отвечает за источник политики режима Auto.

### Встроенные источники

**Antizapret** и **Anticensority** поддерживаются расширением и не редактируются.
**Manual rules only** не добавляет внешнюю автоматическую политику: маршрут
меняют только ваши Site rules и связанные настройки.

Выбор источника сохраняет черновик. Нажмите **Choose source**, а затем глобальный
**Apply configuration**, чтобы сделать его активным.

### Пользовательский источник

Добавляйте custom source только если доверяете его владельцу и точным адресам.
Разрешены HTTPS и loopback HTTP; URL с логином или паролем отклоняется.
Перенаправление проверяется повторно. Не публикуйте приватный URL, query string
или содержимое источника в issue.

Ошибка загрузки не означает, что предыдущие активные данные обновились.
Проверяйте Overview и Maintenance после Apply.

## 4. Site rules

Site rules показывают все явные Proxy и Direct правила.

- Простая запись hostname относится к точному хосту.
- Область домена включает базовый домен и его поддомены.
- Граница публичного суффикса не может стать пользовательской областью.
- Удаление правила возвращает сайт в Auto только после Apply.
- Порядок приоритетов: явный Direct, явный Proxy, обычное решение Auto.

Изменения остаются видимыми как неприменённые. Используйте глобальный Apply;
второго независимого механизма применения в Site rules нет.

## 5. Proxy connections

Раздел организован от общего состояния к деталям:

1. доступность подключений для явных Proxy rules;
2. proxy connections от Automatic routing source;
3. локальные приложения;
4. пользовательские proxy servers;
5. раскрываемые advanced proxy-routing policies.

Количество **Proxy connections available** использует тот же расчёт пригодных
кандидатов, что и маршрутизация. Connection check находится в Maintenance и не
запускается автоматически при редактировании.

### Подключения от источника

Блок **Source-provided proxies** отдельно управляет тем, можно ли использовать
proxy connections выбранного Automatic routing source. Он не включает и не
меняет локальные или пользовательские серверы. Точные технические политики
остаются в раскрываемых advanced settings.

### Локальные приложения

Отключённые подключения компактны: видны название, состояние, требование,
endpoint summary и кнопка **Edit**. Включение или Edit раскрывает существующие
поля хоста, порта и типа; ошибка также оставляет проблемное поле доступным для
исправления.

- **Tor service** — SOCKS5 `127.0.0.1:9050`. Локальная служба Tor должна быть
  запущена. Расширение не переключается автоматически на порт 9150.
- **Tor Browser** — SOCKS5 `127.0.0.1:9150`. Tor Browser должен быть запущен.
  Расширение не переключается автоматически на порт 9050.
- **WARP** — отдельное локальное подключение с текущим значением
  `SOCKS5 127.0.0.1:40000; HTTPS 127.0.0.1:40000`. Соответствующий локальный
  proxy должен быть запущен; автоматического обнаружения WARP нет.

Меняйте defaults только если локальное приложение действительно слушает другой
endpoint. Сохранение или переключение Enabled не запускает приложение и не
доказывает его доступность.

### Пользовательские proxy servers

Сохранённая строка в свёрнутом виде показывает:

- тип HTTP, HTTPS, SOCKS4 или SOCKS5;
- безопасное представление host:port;
- Enabled или Disabled;
- наличие настроенной аутентификации без имени и пароля;
- ошибку или недоступное состояние, если оно уже известно интерфейсу.

**Edit** раскрывает существующие поля type, host, port, username и управления
паролем. **Add custom proxy server** сразу создаёт раскрытую настраиваемую строку.
Новая строка не попадает в активный маршрут до сохранения и глобального Apply.

Порядок пользовательских прокси влияет на порядок попыток. Кнопки вверх/вниз
работают с клавиатуры; порядок меняется только явным действием пользователя.
Remove также требует последующего Apply.

#### Пароль и аутентификация

- Сохранённый пароль никогда не подставляется обратно в DOM или свёрнутую
  сводку.
- Пустое поле нового пароля сохраняет существующий credential согласно
  показанному состоянию **Authentication configured**.
- Замена и удаление пароля выполняются явными отдельными действиями.
- Username, пароль и credential reference не попадают в свёрнутую строку,
  диагностику или правила маршрутизации.

Не используйте реальный пароль в скриншоте или публичном отчёте. Connection check
и успешная proxy-auth — разные проверки.

### Сохранить и применить

**Save proxy settings** сохраняет черновик Proxy connections. Рядом с
изменёнными подключениями появляется **Not applied**, а глобальный
**Apply configuration** остаётся единственным способом изменить активные
правила Chromium. Ни редактирование, ни Enabled, ни reorder, ни connection check
не создают второй Apply и не применяются автоматически.

Раскрываемый блок **Advanced proxy-routing policies** содержит связанные редкие
политики. Настройки верхнего раздела **Advanced** не дублируются здесь.

## 6. Maintenance

Maintenance объединяет действия, которые нужны не каждый день:

- обновление данных Automatic routing;
- расписание периодического обновления;
- ручную **Connection check**;
- очищенные события и диагностический отчёт.

Connection check вторична: она не меняет Auto / Proxy / Direct, не включает
прокси, не сохраняет черновик и не является новым Apply. Успешный ответ
подтверждает только проверенный путь; он не доказывает анонимность, отсутствие
DNS-утечек, маршрут всех запросов или успешную аутентификацию каждого соединения.

Не публикуйте сырой browser profile, NetLog, proxy endpoint, URL источника с
query string, credentials, cookies, посещённые URL или содержимое routing data.

## 7. Advanced

Advanced предназначен для редких и потенциально широких политик:

- область собственных proxy connections;
- Direct replacement и noDirect/fallback behavior;
- совместимость и явная миграция старых настроек;
- экспертные операции с состоянием.

Меняйте эти параметры только если понимаете их влияние. Safe defaults сохраняют
узкую область собственных подключений, не заменяют Direct на Proxy и допускают
Direct там, где его возвращает источник. Настройка, принадлежащая Proxy
connections, показывается только там; дублирующих переключателей нет.

## 8. About

About показывает версию расширения, опубликованный release, ссылки текущего
репозитория, лицензию и атрибуцию исходного проекта. В выпуске `v0.0.3.0`
показывается версия `0.0.3.00`; для проверки опубликованного файла используйте
[страницу стабильного выпуска](../../README.md#текущий-стабильный-выпуск).

## Если что-то не работает

Начните с **Overview**: он различает незавершённую настройку, намеренный Off,
неприменённый черновик и внешнего владельца. Затем откройте Maintenance только
для соответствующей проверки. Пошаговые действия собраны в
[руководстве по решению проблем](TROUBLESHOOTING.md).
